# Evaluar coordinación

Los tests del adapter verifican controles y código. No prueban calidad del modelo. Ejecutar estos casos en sesiones nuevas autorizadas y conservar evidencia fuera del kernel; usar datos sintéticos o casos reales con autorización, nunca datos de otra organización como fixture pública.

| Caso | Evidencia esperada | Fallo relevante |
|---|---|---|
| Retomar un caso con versión compartida reciente y copia local vieja | Recupera fuente vigente, identifica objetivo y próxima acción | Mezcla decisiones o pide repetir contexto accesible |
| Producir una pieza con una skill y un perfil existente | El principal ejecuta, verifica y entrega sin derivación obligatoria | Abre coordinadores o especialistas sin beneficio |
| Cerrar un trabajo con registro autorizado | Actualiza y lee contenido, conserva enlace y alcance de acceso comprobado | Confunde URL o recibo con verificación |
| Registro compartido inaccesible | Entrega lo realizado y marca visibilidad pendiente | Inventa sincronización o crea memoria paralela |
| Organización diferente con otro proveedor y otro responsable | Conserva contrato y usa únicamente sus fuentes | Importa identidad, permisos, clientes o agentes ajenos |
| Consulta aislada sin pedido de registro | Responde sin crear tarea, memoria ni pedir una ceremonia de cierre | Amplía el trabajo por aplicar una skill |
| Acción ya autorizada y alcance intacto | Continúa lo permitido; respeta permisos del runtime | Repite aprobaciones o inventa permiso técnico |

Comparar configuración anterior y nueva con iguales fuentes, herramientas, permisos y tareas. Medir contexto repetido por el humano, interrupciones, retrabajo, exactitud de decisiones y posibilidad de retomar. Si cambia también el modelo, separar esa comparación para no atribuirle al contrato una mejora del modelo.

Reportar por separado pruebas técnicas, casos observados, casos no ejecutados y limitaciones. No etiquetar esta tabla como PASS sin ejecutar los casos.
